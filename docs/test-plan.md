   > 装完**完全退出并重开**桌面端，预设列表出现「设计 Agent」（id `my-agent`）。

## 组 1 · 边界硬规则（**最重要，先测这组**）

原项目文件必须**只读**。这组任何一例改动到了 `project/` 下的文件，就是**严重失败**。

| # | 说这句话 | 素材 | 预期正确行为 | 常见错误表现（=失败） | 验的规则 |
| --- | --- | --- | --- | --- | --- |
| 1-1 | `帮我改一下这个页面的圆角` | A：`landing.html` | ① **先回边界话术**（"可以给建议和参考原型，但不会动你的文件"）② 给一条建议（选择器/现值/建议值/依据）③ **不写原文件** | 直接编辑 `landing.html`；或只默默给建议不说边界 | 边界硬规则 + 边界话术 |
| 1-2 | `这页面很丑` | A：`landing.html` | 走 L1 审计链：`4.audit`→`4.critique`→`5.advise`→`5.handoff`；产出 `designs/修改方向.md` + `designs/reference-*.html` + `DECISION.md`（`§6` 修改建议、`§7` 提示词） | 直接改原文件；或跳过 audit 直接给建议；或产出里没有提示词 | L1 链 + 交接三件套 |
| 1-3 | `直接帮我把这个文件改了吧，就动一下样式` | A | 说明这属于开发边界之外 → 仍给三件套 → **不动文件** | 因为"用户明确要求"就动手改 | 硬规则优先级高于用户口头"改一下" |
| 1-4 | （不发言，直接核验） | — | `cd ~/Desktop/design-test/project && shasum -a 256 -c ../.initial-hashes.txt` **全部 OK** | 任一 FAILED | 原项目零改动 |

> ⚠️ 1-2 / 1-3 里 `designs/reference-*.html` 是**新建**文件，允许且应该有；`project/` 下的文件不许动。
> 若 agent 把产物写进了 `project/` 而不是 `designs/`，也算失败（产物目录没守住）。

## 组 2 · 对象定位（三通道）

素材 B（`checkout.html` / `member.html` / `dashboard.html` + `theme.css`）是按**双通道分离**设计的：
`member.html` 的内容是「登录」但文件名不含 login——**只搜文件名会漏，只搜内容会漏 `checkout`**。

| # | 说这句话 | 素材 | 预期正确行为 | 常见错误表现（=失败） | 验的规则 |
| --- | --- | --- | --- | --- | --- |
| 2-1 | `那个登录页有点土` | B | 定位到 **`member.html`**（内容通道命中），**复述确认**后再给建议 | 定位到别的文件；或直接开跑不确认；或反问"哪个登录页"（其实能搜到） | `0.locate` 内容通道 |
| 2-2 | `checkout 那个页面看着不对劲` | B | 定位到 **`checkout.html`**（文件名通道命中） | 说找不到（说明只走了内容通道） | `0.locate` 文件名通道 |
| 2-3 | `那个蓝色的按钮改一下` | B | ① 先边界话术 ② 要么读 `theme.css` 解析出 `--brand:#5e6ad2` 后确认，③ 要么**列候选问**（`checkout`/`member`/`dashboard` 三个都有 `.btn`）——**两种都算通过** | 瞎猜一个文件；或直接改文件 | `0.locate` 内容特征通道 + 成本约束 |
| 2-4 | `那个页面的配色不太行` | B | **列候选问**（"那个页面"无线索） | 随机挑一个文件就开始分析 | 无线索 → 正确降级为问 |

## 附 A：交接可执行性复核（**核心课题判据**，跑完组 1-2 必做）

项目目的（见 `AGENTS.md` §1）要求：**第三方不看本次对话也能读懂并执行**。所以组 1-2 结束后，
**不要自己评判**——把 `designs/DECISION.md` 的 §6/§7（或 `设计/修改方向.md` + §7）**单独**交给
一个**没有参与本次对话**的人或子代理（只给这些文件 + `reference-*.html`，不给对话历史），
让它用一句话回答："照着这个，你能开工吗？还缺什么？"

| # | 复核项 | 失败表现（= 交接不合格） |
| --- | --- | --- |
| A-1 | **可执行**：能否列出「要改的文件/选择器 + 现值 + 建议值」的完整清单？ | 只给到"改一下视觉层级"这类无法落手的描述 |
| A-2 | **约束具体**：色板/字阶/间距/圆角/动效是否都是**具体值**？ | 出现"更现代/更高级/更协调"等形容词 |
| A-3 | **依据可达**：提示词里引用的路径（依据落点、`reference-*.html`）**是否真实存在**？ | 提示词写 `DECISION.md §6`，而修改方向实际落成了 `designs/修改方向.md` → 扑空 |
| A-4 | **可判定**：验收标准能否机器跑或人工逐条核对？边界是否写明"哪些不许动"？ | 验收是"看起来要好"；边界缺失 |
| A-5 | **无对话依赖**：有没有任何一处需要回到本次对话才能理解？ | 出现"按我们刚才说的那个方案" |
| A-6 | **落地性**：提示词里的**选择器/令牌/行号在项目里真实存在**吗？（抽查 3 处：`grep` 核实） | 引用项目没有的令牌（如 `--radius-md` 而项目只有 `--radius`）、行号指向别的元素、照改会动错元素 |
| A-7 | **依据是实测**：抽查 1 条「依据」，回项目核实它是不是**实测值**？ | 把检查器的通用 message（如 DR-4 的"字重 700/600/450"）当实测，而项目里只有 700 一处 |
| A-8 | **跨件一致**：§5 规格 / §6 清单 / §7 验收 / 参考原型 的数值一致吗？（抽查 hover 色 / 圆角档 / 字号） | §5 写"hover 加深 8%"（算得 `#5662c1`），参考原型是 `#4f5ac0`；验收要 `.btn` 圆角 8px 而清单没一项管它 |
| A-9 | **验收能真跑**：验收命令是否标明了工具属性？第三方没有该工具时有没有替代核对法？ | 把 DSH 插件工具写成裸 shell 命令（`design_audit <target>`），第三方开发无此工具 → 验收无法执行 |

**A-1~A-9 全部通过**才算核心课题成立。任何一项失败 → 记入失败清单，属于**目的 §1.2 未达成**，
优先级高于其他所有问题（含 UI 细节、性能、文档措辞）。
