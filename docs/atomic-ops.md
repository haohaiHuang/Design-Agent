# 原子动作模型（Atomic Ops）— Design-Agent 流程解耦设计

> 状态：**DSH 侧验证中**（本地已生效）。验证跑顺后再回灌上游 [my-pi-skills](https://github.com/haohaiHuang/my-pi-skills) 的 `skills/design-references`，避免 pi / DSH 两平台同时改出分叉。

## 一、为什么拆：现状的三个问题

当前结构是 `阶段判定（5 档）→ 场景分支（A/B/C）→ 环节（0-4）`。环节内部其实已有 20+ 子步骤，且已做条件化（`5b 事实验证门` / `1a 品牌资产门` / `2b 概念发散` / `9a/9b` / `9 减法 pass`）。
**粒度不是瓶颈，缺的是三样东西**：

| # | 问题 | 后果 |
| --- | --- | --- |
| ① | **入口单位是"环节"而非"步骤"** | 进入某环节就得顺序走完它的全部子步骤；无法只跑其中一步 |
| ② | **子步骤没有输入/输出契约** | 无法中断续跑、无法交接、无法并行；产物散落在对话里 |
| ③ | **门禁绑在环节末** | 中途进入会丢掉该有的用户确认点 |

附带问题：**工具与步骤是散文绑定的**（`design_route` 写在 1b、`design_audit` 写在 4.1），"只扫一下"这类请求需要反推该调哪个工具。

## 二、切分标准

**以"可独立交付 / 可交接"为单位切**，不按"叙述步骤"切。理由：op 的价值在于可以被独立请求、独立产出、独立验收；过细会推高路由推理负担与上下文预算压力（技能已有"铁律 10 加载预算"）。

## 三、14 个原子动作

| op | 名称 | 输入 | 产物（落盘） | 工具 / 校验 | 门禁 |
| --- | --- | --- | --- | --- | --- |
| `0.locate` | 对象定位 | 指代 / 截图 / URL | `designs/target.md`（对象 + 定位依据） | glob + grep + 读文件（**三通道**） | 多命中/全未命中时用户选 |
| `0.facts` | 事实验证 | 产品/品牌/版本/规格 | `designs/facts.md` | `web_search`（+`tool-web` fetch） | 自动 |
| `0.assets` | 资产盘点 | 项目现有设计系统/token/品牌资产/规则文件 | `designs/assets.md`（继承清单 + 冲突项） | read / grep | 有冲突时用户裁决 |
| `0.brief` | 意图澄清 | 需求 + facts + assets | `designs/brief.md`（场景/格式/受众/目标/硬约束/形态） | 问询 ≤3 问 | 用户确认 |
| `1.route` | 需求路由 | brief / 需求原文 | `designs/route.md`（主桶+次桶） | `design_route` | 自动 |
| `1.extract` | 参考萃取 | URL / .fig / 截图 | `designs/tokens-<name>.md` | `dembrandt` / `defuddle` / openpencil | 自动 |
| `1.diverge` | 候选发散 | route + tokens | `designs/candidates.md` + `candidate-*.html` | `design_lookup` + `design_diversity` | 用户选定 |
| `2.constrain` | 约束转译 | 选定候选 / tokens | `designs/constraints.md`（≤10 条，每条带来源） | 可执行+可校验自检 | 用户确认 |
| `3.build` | 实现产出 | constraints | `designs/<name>.html` | `/* 约束N */` 注释齐全 | 自动 |
| `4.audit` | 机器校验 | 产物 | gate punch list | `design_audit` | 自动 |
| `4.critique` | 独立评审 | 截图 + **方向锁** + moodboard（可省） | 四维评分 | `ego-browser` 截图 + critic 子代理 | 自动 |
| `4.refine` | 减法 / 回炉 | 产物 + 约束集 | `designs/refine.md` | Type A 机器抓 / Type B 人定清单 | 用户确认 |
| `5.advise` | 修改建议 | 现有产物（只读） | `designs/修改方向.md` | 五要素齐全自检 | 用户确认 |
| `5.handoff` | 交付交接 | 见「双形态」 | 见「双形态」 | `present` | 自动 |

### 三条硬性串联规则（干跑模拟发现的三处漏洞）

1. **`0.facts` 触发时先于 `0.brief`** —— 需求涉及具体产品/品牌/版本/规格时先核实再问询（技能原文："本门先于问询——事实错了，问什么都是歪的"）
2. **任何会产出 HTML 或约束集的链，必跑 `0.assets`** —— "盘点项目已有设计资产"是最高优先级参考（有设计系统就继承，禁止推翻重来）；跳过就是丢掉最大识别度来源。L0 纯查/纯萃取除外
3. **L1 链首步补形态判定** —— `3.build` 之前必须完成形态判定（Mac 窗口模拟/网页/手机框/画布），可只跑 `0.brief` 的轻量子集（形态 + 硬约束）

### 两个需要参数化的 op

**`4.critique` 的方向锁来源（两种场景都要能跑通）**
- 有 `2.constrain` 产物 → 直接用约束集当方向锁
- **审计迭代场景（无约束集）** → 先按技能 `references/ui-quickfix.md` 的**方向锁五维**从现有产物 infer 方向，再喂给 critic；moodboard 可省。infer 不出 → 降级 huashu 5 维自评并**明示降级**

**`5.handoff` 双形态**
- **从零新建** → `DECISION.md`（§1-4）+ `present` 声明交付物（**不产出**开发交接提示词）
- **改现有产物** → `DECISION.md` §5 修改建议 + §6 开发交接提示词 + `reference-*.html`

## 四、两个解耦机制

### 1. 产物契约（artifact contract）

op 之间**只通过 `designs/` 下的文件交接**，不靠对话上下文。四个副产品：

- **中途进入**：某 op 的输入产物已存在 → 该 op 可单独启动
- **断点续跑**：`constraints.md` / `修改方向.md` 就是断点
- **并行**：多个参考站可并行 `1.extract`；`4.audit`（静态分析）与 `4.critique`（截图评审）可并行
- **交接**：产物即交接包（复用已定义的"交接三件套"）

### 2. 门禁挂 op（declarative gate）

每个 op 自带 gate 声明（`用户确认` / `用户选定` / `自动`），而不是"每环节末确认一次"。中途进入的请求同样受正确门禁保护。

## 五、入口判定：意图归一化 → 对象定位 → 选链

**日常语言是"症状 + 模糊指代"**（"这页面看着怪怪的""那个登录页有点土""帮我弄好看点"）。
第一版按"看产物"直接选链**在真实口语下会大面积误判**（口语化干跑：12 句只有 1 句干净命中，见 §7）。
因此入口判定固定三步：

### 第一步 · 意图归一化（口语 → `(对象, 意图, 约束)`）

| 意图 | 识别信号（口语） | 走哪条链 |
| --- | --- | --- |
| **新建** | "做个/弄个/设计一个 X""我们是做 X 的，想弄个官网" | L2 全流程 |
| **改进现有** | "很丑/怪/土/不协调/高级一点/优化一下/改一下"（针对**已有**产物） | L1 审计迭代 |
| **纯查** | "扫一下/检查下/有没有 AI 味" | L0 `4.audit` |
| **纯萃取** | "看看这个网站/这张图的设计""我要那种风格" | L0 `1.extract` |
| **状态查询** | "上次那个改了吗/做到哪一步了" | **不跑链**，查 `designs/` 产物回答 |

"改一下/优化一下"这类**空动词必须结合对象判定**：对象是已有产物才算"改进现有"，否则归新建。

### 第二步 · 对象定位（`0.locate`）

用户用指代（"那个登录页/那个按钮"）或只给截图/URL 时，**先定位对象再选链**。
三通道搜索——**缺任一通道都会漏（实测验证）**：

| 通道 | 手段 | 实测例子 |
| --- | --- | --- |
| 1. 文件名 | `glob` / `ls` | `login` → `login.html`（注意：`grep -r` 搜内容**找不到文件名**，两通道互不覆盖） |
| 2. 文件内容 | `grep -ril` | `登录` → `login.html` |
| 3. 内容特征解析 | 读文件解析 | "那个蓝的" → 需解析 CSS 变量/主题文件才懂 |

命中 1 个 → 复述确认；命中多个 → **列候选让用户选**；**全未命中 → 给候选清单问，禁止瞎猜**。

### 第三步 · 选链与链内定位

- **① 选链**：按意图 + 对象定 L0/L1/L2（见「三档粒度」）
- **② 链内定位**：取链内**第一个「输出缺失」的 op** 作为入口
  （例：`constraints.md` 在、产物 HTML 不在 → 入口是 `3.build`，不重跑前面的 op）
- **③ 条件 op 只在触发时进链**：`0.facts` 仅当需求含产品/品牌/版本/规格时进链——它没有输入产物，
  若不加此限制会变成**所有任务的入口**（见 §7 GAP-8）；L0 请求不进 L2 链，
  `0.assets` 在纯查/纯萃取链里不进链。

拿不准时一次问清（≤3 问）；仍判不出 → 按产物存在性兜底（**有产物 → `4.audit`；无产物 → `0.brief`**）

### 歧义问询协议（≤3 问；优先级：对象 > 意图 > 范围）

- **只问会改变动作的问题**；能从上下文/搜索推断的不问
- **给候选选项，不用开放问句**（"你说的是 A 还是 B？"优于"你指的是哪个？"）
- 典型三问：① 对象〔列候选〕② 意图（**只给建议** 还是 **做个参考原型**？两种都不动你的文件）③ 范围（只改一处还是整页）
- **截图/URL 的角色必问**："我要这种风格"（→`1.extract` 参考）还是"帮我看看/改这个"（→`4.audit` 待改对象）？**两者链完全不同，不许猜**。

### 非请求输入与多目标

- **停止语**（"算了/就这样吧"）→ **不启动任何链**，确认收尾
- **状态查询** → 查 `designs/` 产物存在性回答，不跑链
- **多目标**（"顺便把 X 也做了"）→ **拆成 N 条独立链**，列 `对象+意图`，排优先级，逐条确认后依次执行

### 边界话术

口语"改一下"就是"你去改"，与「绝不改原项目文件」硬规则**直接冲突** → 收到这类口语时
**先回一句边界说明**（"我可以给你修改建议和参考原型，但不会动你项目里的文件"），再按 `5.advise` 走。
**不要沉默地只给建议**——用户会以为你在拖延。

### 三档粒度

| 档 | 含义 | 例子 |
| --- | --- | --- |
| **L0 单点** | 只跑一个 op | "扫一下有没有 AI 味" → `4.audit`；"看看这个网站的设计系统" → `1.extract`（止于此，不进流程） |
| **L1 分段** | 跑一条子链 | "用 Linear 那种风格做" → `0.assets` → `0.brief`(形态) → `1.extract` → `2.constrain` → `3.build` → `4.audit` |
| **L2 全流程** | 从零新建 | `0.facts`(触发时) → `0.assets` → `0.brief` → … → `5.handoff` |

**L0 轻量豁免**：单项微调（改一个值/一个组件/一行样式）只给「一条建议（选择器/现值/建议值/依据）+ 一行提示词」，跳过参考原型与完整 `DECISION.md` —— 别用重交付压轻请求。

## 七、干跑模拟记录（2026-09-21）

### 第一轮：任务式语言（8 类请求）

按"盘点 → 选入口 op → op 链 → 门禁 → 产物 → 边界"对 8 类请求做了一次完整干跑，其中
`4.audit` 用真实检查器执行（样例页检出 16 项：error 5 / warn 7 / info 4）。

**跑通确认**：`4.audit` 单点、`1.extract` 纯萃取、L0 入口判定、边界硬规则（全程未碰原项目文件）。

**发现并已修的 8 个问题**：

| # | 问题 | 严重度 | 修法 |
| --- | --- | --- | --- |
| GAP-1 | `4.critique` 在审计链上输入契约不满足（无方向锁/moodboard） | 高 | critic 输入改为「截图 + 方向锁 + moodboard(可省)」；审计场景用 ui-quickfix 方向锁五维 infer |
| GAP-5 | 丢失「现有资产继承」（最高优先级参考） | 高 | 新增独立 op `0.assets`，产出/约束类链必跑 |
| GAP-6 | 入口判定措辞歧义 → 续跑时跳过 `3.build` | 高 | 改为两步判定：输入缺→不可执行；输入齐+输出缺→入口候选，取最靠前 |
| GAP-2 | L1 链跳过形态判定 | 中 | L1 首步补 `0.brief` 轻量子集（形态 + 硬约束） |
| GAP-4 | `0.facts` 应**先于** `0.brief`（与技能冲突） | 中 | 提为串联规则第 1 条 |
| GAP-3 | `5.handoff` 未区分"新建/改现有" | 中 | 定义双形态产物 |
| GAP-7 | L0 单项微调产出过重 | 低 | 加 L0 轻量豁免 |
| GAP-8 | 修 GAP-6 时引入新坑：`0.facts` 无输入产物，按"输入齐+输出缺"判定会**成为所有任务的入口** | 高（复跑发现） | 入口判定改为**三步：先选链 → 链内取最早缺失产物 → 条件 op 只在触发时进链** |

### 第二轮：口语化语言（12 句日常说法）

用用户真实会说的话（不精准、描述性、带模糊指代）重跑，环境：`project/` 有
`login.html` / `landing.html` / `dashboard.html` / `styles/theme.css`，`designs/` 空。

**结果：12 句里只有 1 句能干净命中** —— 说明第一版入口表是按"精确任务短语"设计的，
与真实口语的"症状 + 模糊指代"形态不匹配。

同时实测了**定位可行性**：
- 文件名通道与内容通道**互不覆盖**——`grep -ril login` 找不到 `login.html`（文件名含 login 但内容没写），必须 `glob`/`ls` 补上
- 感官类指代（"那个蓝的"）**必须读文件解析 CSS** 才可能定位

**发现并已修的 6 个新缺口**：

| # | 问题 | 严重度 | 修法 |
| --- | --- | --- | --- |
| GAP-9 | **缺「意图归一化」**：直接拿口语选链会误判（"看着怪怪的""弄好看点""高级一点"全判错） | 高（结构性） | 选链前插入归一化：口语 → `(对象, 意图, 约束)`，意图归 5 类 |
| GAP-10 | **缺「对象定位」**：指代无处解析；persona 里没有任何定位规则 | 高（结构性） | 新增 op `0.locate`，三通道（文件名/内容/内容特征） |
| GAP-14 | **问询协议缺位**：规则说"拿不准问清（≤3 问）"但**没规定问什么**；技能的环节 0 问询只覆盖新建场景 | 高（结构性） | 补「歧义问询协议」：优先级 对象 > 意图 > 范围，给候选选项 |
| GAP-11 | **截图/URL 角色歧义**：参考 vs 待改对象，链完全不同 | 高（高频） | 规定必问角色，不许猜 |
| GAP-12 | **多目标请求无规则**（"顺便把 X 也做了"） | 中 | 拆 N 条独立链，排优先级逐条确认 |
| GAP-13 | **非请求输入无规则**（停止语 / 状态查询） | 中 | 停止语不启动链；状态查询查 `designs/` 产物回答 |

附带风险（已用话术化解）："那个蓝色的按钮**改一下**"——口语的"改一下"与「绝不改原项目」硬规则直接冲突，
现在规定**先回一句边界说明**再走 `5.advise`，避免既违规或显得死板。

## 八、回灌上游的触发条件（验证清单）

在 DSH 侧跑顺后再动 `my-pi-skills`，验证项：

1. 入口判定准确：至少 5 类不同请求（L0 单点 / L1 分段 / L2 全流程 / 审计迭代 / 纯萃取）都能命中正确 op，无"无谓前滚"
2. 产物契约成立：中断后能从 `constraints.md` 或 `修改方向.md` 续跑（**真跑一次中断续跑**）
3. 门禁不错位：中途进入的请求仍会在正确的 op 停下确认
4. 边界不破：`5.advise` / `4.*` 全程不碰原项目文件
5. 上下文预算可控：单次任务读取的参考文件数未明显上升（对照"铁律 10"）
6. 串联规则落地：`0.facts` 先于 `0.brief`、产出链必跑 `0.assets`、L1 补形态判定——三项在真实会话中各验一次
