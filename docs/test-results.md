## 跨例发现

### ⚠️ 5-1 推翻的判据：`scrollWidth === clientWidth` 在有 `overflow-x: clip` 时失效

5-1 指出：`overflow-x: clip` 会把文档级滚动兜住，于是"`scrollWidth === clientWidth`"这条
"无横向滚动"判据**失去分辨力 —— 内容被裁掉也照样通过**。它改为元素级检测才测出真溢出。

**这削弱了此前若干会话的同类结论**（我把它们当作已验证记录过）：

| 会话 | 当时的表述 | 现在怎么看 |
| --- | --- | --- |
| 1-2 | 四页 320–1920 无横向滚动 | 判据失效，**证据强度下降** |
| 3-3 | 四视口实测无元素超出 | 元素级检测，**仍成立** |
| 3-4 | 九档宽度（320→1920）无横向滚动 | 判据失效，强度下降 |
| 3-6 | 九档宽度（320→1920）无横向滚动 | 判据失效，强度下降 |
| 4-3 | iframe 五档 `scrollWidth == clientWidth` | 判据失效，强度下降 |
| 3-1 | "无横向滚动，**但内容溢出被裁**" | 当时就点出了掩盖现象，判断正确 |

→ 修复清单新增一条：**把"溢出验收"写成元素级检测（逐元素比较 `getBoundingClientRect` 与视口宽，
并区分"在滚动容器内可达"与"真溢出"），并在 preset/技能里注明 `clip` 会让滚动条判据失效**。
这一条同时是回灌 `design-references` 的方法论修正，价值高于单个技能细节。

## ⚠️ 一处数值错误（我方独立复算发现）

报告称"白字在渐变上从 4.70:1（起点）漂到 **3.37:1**（中点）跌破 4.5:1"。我方按 WCAG 公式复算了三种插值模型：

| 取色方式 | 白字对比度 |
| --- | --- |
| 起点 `#5e6ad2` | **4.70** ✓（与它一致） |
| sRGB 通道中点 `#7563e4` | **4.51** |
| 线性光平均后回 sRGB `#7763e5` | **4.47** |
| 终点 `#8b5cf6` | **4.23** |
| 全渐变扫描最差点（t=0.96） | **4.24** |

即**最差点是紫端的 4.23:1，不是 3.37:1**（3.37 对应比终点更浅的紫，像是把颜色往白方向偏了约 20% 算的）。
**结论方向不受影响**：4.23 < 4.5，确实跌破 AA，`gate 2`/`gate 46` 的定性判断仍成立。
→ 记为**数值精度缺陷**（交付物里的数字必须能复算通过），并提示这类"渐变色上的对比度"应当用**全渐变扫描取最差值**，
而不是只报起点/中点/终点。

**边界诚实**：报告 §5 明说"移动端（375px）截图因本机 Chrome 无头模式超时未取到……结论方向不变，但**未做逐视口实证**"。
